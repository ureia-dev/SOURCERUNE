# SOURCERUNE UI_02

Status: reserved as the second first-class SOURCERUNE layout.

## Naming note

In earlier design discussion, the current UI_01 reference was temporarily called UI_02 before being renamed to UI_01. Therefore **there is not yet a separately locked historical UI_02 geometry in this repository**.

From this point forward:
- `UI_01` means the approved engineer-oriented Scene View layout documented in `UI_01.md`.
- `UI_02` means a genuinely separate second layout.
- Do not duplicate UI_01 and call it UI_02.
- Do not invent UI_02 geometry without an approved UI_02 reference/layout decision.

## Functional requirement

UI_02 must retain full functional parity with UI_01 and the shared `UI_FUNCTION_CONTRACT.md`.

At minimum UI_02 must provide:
- Source.
- Transmission.
- Condition.
- Wall/Cover.
- Distance/Motion.
- Space/Environment.
- Ambience.
- Intelligibility.
- EQ/Tone.
- Mix.
- Spectrum.
- Space Response.
- Signal Flow.
- IN/OUT + Peak/RMS/LUFS.
- A/B/C/D snapshots.
- Preset/state management.
- VST3 automation/state compatibility.
- WEB TEST parameter/state compatibility.

## Locking rule

Before UI_02 implementation begins, lock these items in order:
1. reference image / approved visual direction,
2. native design size and aspect,
3. section boundaries,
4. control ownership per section,
5. permanent numeric readouts,
6. responsive/scaling behavior,
7. asset list,
8. coordinate/layout specification.

Only after that should VST3 or WEB UI_02 code be written.

## Shared-state rule

UI_02 is a different presentation of the same engine. Switching layouts must not:
- alter sound,
- remap parameter IDs,
- reset parameters,
- change preset meaning,
- change deterministic seed,
- change automation behavior.
